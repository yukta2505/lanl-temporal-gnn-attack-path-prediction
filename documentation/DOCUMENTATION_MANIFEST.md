# Documentation manifest

The project documentation is organized around the supplied synopsis.

## Project scope

- `PROJECT_OVERVIEW.md` — problem, data, implemented components, and measured
  status.
- `USE_CASE_DIAGRAMS_ADDED.md` — current and planned user workflows.
- `diagrams/USE_CASE_DIAGRAMS.md` — synopsis-aligned workflow diagram.

## Technical design

- `theory/GRAPH_NEURAL_NETWORKS.md` — host-graph representation, GraphSAGE,
  pair scoring, explanation, and risk boundaries.
- `theory/TEMPORAL_MODELING.md` — chronological windows, leakage controls,
  temporal-model design, and evaluation cautions.
- `architecture/SYSTEM_ARCHITECTURE.md` and `architecture/DATA_FLOW.md` —
  current components and planned GNN path.

## User and evaluation guides

- `user_guides/QUICK_START.md` — commands for the local data, baseline, and
  dashboard path.
- `../docs/SETUP.md` — dependencies and local data placement.
- `../docs/USER_GUIDE.md` — dashboard input and analyst workflow.
- `../docs/PROJECT_ALIGNMENT.md` — implementation status and next stages.
- `../THGNN_Project_Report.md` — formal project report draft.

The older generic prototype documents are superseded where they describe
unimplemented APIs, roles, or performance figures. Do not use those claims as
evidence for this synopsis project.
